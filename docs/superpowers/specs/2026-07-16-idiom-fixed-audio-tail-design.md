# 成语游戏固定语音尾音与顺序拼接设计

> **已被取代：** 2026-07-17 最终批准方案为自建 Qwen3-TTS 1.7B、`clone_coffee_20s_v1`、`atempo=0.9`、500ms 尾静音和云端固定提示。本文中的 DashScope、80ms 与板端安装方案仅保留为历史记录。

日期：2026-07-16
状态：已被 2026-07-17 最终方案取代

## 1. 目标

解决成语游戏固定语音的最后一个字尚未自然结束就被截断，或静态片段拼接时下一段过早开始的问题。

本次只处理固定单句和固定片段边界，不新增 `idioms/*` 尾音质量扫描，不重生成、不裁剪成语音频，也不修改板端 `audio_out` 播放驱动。仓库现有的成语文件存在性/格式校验和正常播放读取保持不变。

## 2. 已确认现状

完整开场回复文字已经存在，但当前没有一条完整开场音频：

```text
idiom_game/start.wav       = 好呀，我们玩成语接龙。
idiom_game/robot_first.wav = 小机仔先来
```

首轮计划当前为：

```text
idiom_game/start
idiom_game/robot_first
idioms/{成语}
```

云端 `merge_static_audio_paths()` 只是顺序追加原始 PCM字节，没有边界质量检查。它本身不会主动重叠两段声音，但如果前一固定片段的尾音或安静尾部不完整，下一段会紧接在不完整的端点后，听感等同于“上一句没说完就开始下一句”。

板端三条本地提示的测量结果：

| 文件 | 时长 | 连续低能量尾部 | 结论 |
|---|---:|---:|---|
| `idiom_game_presence_1.pcm` | 960ms | 约55ms | 需补安全尾部 |
| `idiom_game_misheard_1.pcm` | 2029ms | 约24ms | 需补安全尾部，并受64KiB上限约束 |
| `idiom_game_idle_exit_1.pcm` | 1680ms | 不足4ms | 必须重新生成或重新取得完整尾音，不能直接在截断点后补零 |

云端固定音频中 `start`、`mode_easy`、`mode_full`、`mode_normal`、`static_error` 等也没有达到统一的安全尾部标准。该检查只针对 `data/static_audio/idiom_game/*`，不进入 `data/static_audio/idioms/*`。

## 3. 范围

### 3.1 开场固定音频

不新增重复的 segment id。复用现有 `idiom_game/start`，将其固定文本和音频改为完整前缀：

```text
好呀，我们玩成语接龙。小机仔先来：
```

首轮正常音频计划改为：

```text
idiom_game/start
idioms/{成语}
```

`idiom_game/robot_first` 素材保留，不删除，但正常开场和兼容文本匹配路径停止引用。

### 3.2 云端固定单句

检查当前运行时可能引用的 `idiom_game/*` 固定单句，包括：

```text
start
robot_no_reply_user_win
challenge_win
mode_easy / mode_normal / mode_hard / mode_full
exit
continue_prompt
retry
not_found
static_error
```

只对未达到尾音标准的固定单句重新生成或补齐安静尾部。停止正常流程引用但仍保留的 `turn_prompt`、`robot_reply`、`pinyin/*` 不纳入本轮质量治理，也不删除。

### 3.3 板端本地固定单句

处理：

```text
你还在吗？
我没听清，请再说一次。
那我们下次再玩吧。
```

输出仍为 `16kHz / 单声道 / 16-bit PCM LE`，沿用原文件路径。

### 3.4 明确不做

- 不对 `idioms/*` 增加尾音、RMS或静音质量扫描，不修改任何成语音频；保留原有存在性/格式校验。
- 不修改 `audio_out.c`、codec关闭或 jitter buffer逻辑。
- 不使用运行时动态 TTS。
- 不恢复正常回复中的 `turn_prompt` 或 `pinyin/*`。
- 不删除 `robot_first` 或其他旧素材。

## 4. 固定音频尾音标准

固定音频必须先判断源音频是否完整，再决定补静音，不能把“被截断的最后一个字”直接淡出。

### 4.1 源完整性门槛

统一使用以下门槛，不允许调用方自行选择不同阈值：

```text
低能量10ms窗：RMS <= 100
源完整性：最后20ms RMS <= 100，且最后采样绝对值 <= 100
安全尾部：连续8个低能量10ms窗，即至少80ms
```

对固定素材的最后20ms计算 PCM RMS，并检查最后采样：

- 最后20ms仍有明显语音能量：判定源尾音可疑，不允许只补零；重新合成。
- 最后20ms已进入低能量且端点接近零：允许保留源音频并补安全尾部。
- 新合成结果仍未达到源完整性门槛：本次生成失败，不能覆盖上一份可用素材。

信号门槛只能证明端点已经平稳，不能从波形数学上证明汉字语义完整；因此重新生成的候选还必须通过人工试听，特别检查最后一个字，再允许进入正式素材。

### 4.2 输出尾部

每条通过检查的固定音频最终保留至少80ms连续安静尾部：

```text
完整语音自然衰减
→ 必要时只在已经低能量的尾部做不超过8ms的归零坡度
→ 补零到至少80ms
```

禁止在仍有明显语音能量的区间做淡出，以免把最后一个字进一步削短。

### 4.3 板端文件大小

板端播放器对单条提示的读取上限为64KiB。处理后的三条 PCM必须同时满足：

```text
文件大小为偶数
文件大小 <= 65536 bytes
尾部安静时间 >= 80ms
```

当前 `idiom_game_misheard_1.pcm` 已有64,924 bytes，不能直接追加80ms。应优先重新生成更紧凑的完整版本；只允许裁掉确认无声的开头或多余尾部，不得裁切语音主体。若候选仍超过64KiB，则判定生成失败，不修改板端文件，也不通过验证。

## 5. 顺序拼接规则

语音片段不采用 crossfade，不允许声音重叠。成语游戏静态计划按以下规则合并：

```text
完整读取前一片段
→ 若前一片段属于 idiom_game/* 固定素材，确认其80ms安全尾部存在
→ 再追加下一片段
```

规则只验证和补齐前一个固定片段，不读取、不裁剪、不改变后续 `idioms/{成语}` 的波形。

首轮唯一边界变为：

```text
完整开场 start
→ start 自身至少80ms安静尾部
→ 原样成语音频
```

单段固定回复在整体结束前也具有至少80ms安静尾部，用于降低板端关闭时截掉最后一个字的风险。

如果固定片段质量校验失败，沿用现有 `idiom_game/static_error` 静态回退；`static_error` 自身必须先通过同样的尾音校验，否则服务启动失败。不得回退动态 TTS。

## 6. 生成与部署

固定句只在准备素材时调用云端已配置的 DashScope TTS一次性生成。生成过程使用临时文件，完成格式、尾音、时长和大小检查后才允许进入本地提交或云端正式目录。

云端 WAV保存到 `data/static_audio/idiom_game/`。三条板端提示由已验证的16k PCM候选写入 `esp_idf_demo/spiffs/`，随固件构建进入 `storage.bin`。

由于 TTS Key只存在云端，而板端 PCM必须进入本地 Git，候选生成顺序固定为：

```text
本地完成生成/验证脚本
→ 将一次性脚本或明确文本参数传到云端临时目录
→ 云端在独立临时输出目录生成候选，不覆盖生产素材
→ 自动验证候选格式、端点、80ms尾部和大小
→ scp候选回本地工作区
→ 本地人工试听并运行测试、ESP-IDF build
→ 用户批准后提交并推送代码与三条板端PCM
```

云端 `data/static_audio` 不进入 Git。正式部署时从同一批已验证候选或其带校验和清单复制到生产目录，复制完成后再次校验，之后才允许重启18111。候选批次必须记录文本、模型、voice、字节数和 SHA-256，防止本地固件与云端使用不同批次。

部署顺序：

```text
候选已生成、回传、试听并验证
→ 提交并推送 merge
→ bundle更新云端代码
→ 按候选清单安装并复验云端固定WAV
→ 重启18111
→ 本地ESP-IDF build
→ 完整flash（必须包含storage.bin）
→ monitor实机试听
```

## 7. 测试与验收

### 7.1 自动测试

- 首轮计划严格为 `idiom_game/start + idioms/{成语}`，不再引用 `robot_first`。
- 新增的尾音质量验证只遍历 `idiom_game/*` 和三条板端 PCM，测试确认不会对 `idioms/*` 调用尾音分析；原有存在性/格式校验保持不变。
- 每条被引用的固定音频满足16kHz、单声道、PCM16和至少80ms安静尾部。
- 高能量端点不能通过“直接补零”修复路径。
- 三条板端 PCM均不超过64KiB。
- 拼接结果中前一固定片段的全部样本和80ms安全尾部都位于下一片段之前，测试确认没有重叠或截断。
- `static_error`不合格时启动失败，不回退动态 TTS。
- 现有 realtime、voice_skills、static_audio、ESP assets测试和 ESP-IDF build通过；既有过时 Volcengine断言继续单独标注。

### 7.2 实机验收

依次试听：

1. 开场完整说完“好呀，我们玩成语接龙。小机仔先来”后，再开始成语。

3. “我没听清，请再说一次”最后的“次”自然结束。

6. 后续正常接龙的成语素材与原版本完全一致。

## 8. 成功条件

- 不再出现固定语音最后一个字戛然而止。
- 拼接时上一固定片段完整结束后才进入下一片段。
- 不修改任何成语音频。
- 不引入运行时 TTS成本。
- 普通咖啡问答、持续游戏 WebSocket、VAD和 ASR行为不变。
