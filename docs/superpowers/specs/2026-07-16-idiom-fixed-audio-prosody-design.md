# 成语接龙固定音频语速与拼接听感修订设计

> **已被取代：** 2026-07-17最终批准方案为自建Qwen3-TTS 1.7B、`clone_coffee_20s_v1`、`atempo=0.9`、500ms尾静音和云端固定提示。本文中的DashScope、80ms、板端96KiB方案仅保留为历史记录。

日期：2026-07-16
状态：用户已批准方案 A，并批准“显示文本保留冒号、静态音频使用逗号延续语气”。

## 问题结论

上一批候选满足 16kHz、单声道、PCM16LE、源末尾 20ms 安静和至少 80ms 静音尾，但人工试听仍确认最后一个字有截断感且语速偏快。该检查只能证明音频末端存在静音，无法判断最后一个汉字是否以自然韵律完整收音。

诊断已排除板端播放器、PCM→WAV 预览转换和本次 24k→16k 分片重采样。当前离线实时 TTS 使用默认 `speech_rate=1.0`，且没有传递句尾/韵律指令，是本轮要修正的生成入口。

## 批准方案

### 显式生成参数

离线固定素材生成必须显式传递：

```text
speech_rate: 0.82 / 0.85 / 0.90（试听阶段分别生成）
instructions: 语速舒缓，逐字清晰；每句话最后一个字必须完整、自然收音，不要吞音或突然截断。
```

运行时动态 TTS 调用不传覆盖参数时保持原行为，不能因本次离线素材修复改变普通咖啡问答链路。

### 开场拼接韵律

用户看到和业务返回的文本继续使用：

```text
好呀，我们玩成语接龙。小机仔先来：{成语}。
```

`idiom_game/start` 的静态合成输入改用：

```text
好呀，我们玩成语接龙。小机仔先来，
```

逗号仅影响 TTS 延续语气，不改变业务展示文本。运行时继续使用严格顺序 PCM 拼接：

```text
start 固定 PCM + 原始 idioms/{成语} PCM
```

不使用交叉淡化、重叠、裁剪或成语音频分析。试听必须包含至少一个真实成语拼接样本，不能只验收孤立前缀。

### 板端容量

三条成语游戏本地提示音专用上限从 64KiB 提高到 96KiB：

```text
idiom_game_presence_1.pcm
idiom_game_misheard_1.pcm
idiom_game_idle_exit_1.pcm
```

其他本地提示音仍保持 64KiB。`audio_out_play_pcm_file()` 已按固定小块流式读取，`max_bytes` 是读取停止上限，不会一次申请 96KiB RAM。不得修改 `audio_out.c`；在 `main.c` 为成语提示调用传入独立的 96KiB 上限。

### 人工试听门槛

自动校验继续检查格式、哈希、大小和至少 80ms 安全静音尾，但不再把它称为“尾字自然”。每个语速批次只生成：

```text
idiom_game/start
三条 board 提示音
start + 一个真实成语的合并试听 WAV
```

用户从 `0.82 / 0.85 / 0.90` 中选定语速并确认尾字与拼接后，才按该参数生成完整 12 条云端固定素材和 3 条板端素材。试听未批准前，不安装云端生产素材、不提交、不烧录。

## 测试要求

- 实时 TTS 会话能接收可选 `speech_rate` 与 `instructions`，默认调用不改变。
- 固定素材生成器把显式参数传入实时 TTS，并写入清单。
- 部分试听批次只能包含显式允许的固定段，禁止 `idioms/*` 和 `pinyin/*`。
- 三条成语板端提示允许不超过 96KiB；其他板端提示仍保持原 64KiB 约束。
- `start` 的业务文本保持冒号，合成输入使用逗号。
- 合并试听输出必须逐字节等于 `start_pcm + idiom_pcm`。
- 现有 realtime、voice_skills、ESP 守卫和 ESP-IDF 5.5.4 build 必须通过；旧 Volcengine 默认断言继续单独报告。
